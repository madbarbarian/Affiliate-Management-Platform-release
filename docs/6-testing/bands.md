# モックが見ていない帯域

> 2026-09-10。1日で初歩的なバグを8件出したあと、**同じ場所から出続ける理由**を
> 数え上げたもの。次に「テストは全部通っているのに動かない」が起きたとき、
> まずこの表を見る。

`test/helpers.ts` は会社まるごとを組み立てる — 固定した時計、連番のid、
メモリのストア、そして**全部のモックアダプタ**。ドメインにとってこれは正しい。
1日を何度でも同じように再生できる。

**そして、置き換えたものは全部テストの外に出る。**

## 8件は全部そこにいた

| 出たもの | どの帯域 | いつ分かったか |
|---|---|---|
| `maxItems` で全ロールのスキーマが400 | 実APIに送るリクエストの中身 | 本番の初回呼び出し |
| `effort` を受け付けないモデルに送って400 | 同上 | 本番2日目 |
| `(s) => {...}[s]` で画面のスクリプトが全死 | ブラウザが実行するJS | 利用者がブラウザのコンソールを開いた |
| `\w` が食われて `{n}` が置換されない | 同上 | 上と同時 |
| `#/ventures/` の正規表現が壊れる | 同上 | 上と同時 |
| 失敗が監査ログに残らない | サイクルが失敗する経路 | D1を直接引いて |
| 回復したサイクルが失敗を名乗り続ける | 同上 | 利用者が画面を見て |
| 全アカウントの見出しが空 | ブラウザが実行するJS | **ハーネスの初回実行** |

**1件もテストが落ちていない。** どれも、そのとき通っていたテストが
一度も通らない場所にあった。

## 帯域と、いま何があるか

| 帯域 | 何がモックに置き換わるか | 守っているもの |
|---|---|---|
| **実APIのリクエスト本文** | `MockProvider` はリクエストを一度も見ない | `test/anthropic.test.ts` — 本物のHTTPサーバを本物のSDKの前に立てて、送っている本文を読む |
| **`output_config.format` のスキーマ** | モックは何でも受け取る | `test/schema.test.ts` — ロールが実際に送るスキーマを歩く |
| **ブラウザが実行するスクリプト** | 何も無かった（テストはページを文字列として読むだけ） | `test/page-harness.ts` — 小さなDOMと、本物のルータに向けた `fetch` でページを実行する。`console.test.ts` の「パースできるか」「プレースホルダが残っていないか」も |
| **引数の振り分けと、ディスクからの設定読み込み** | `helpers.ts` は設定をオブジェクトで渡す | `test/cli.smoke.test.ts` — 本物のバイナリを spawn する |
| **アダプタの配線とバインディング** | 全部モックアダプタ | `test/worker.test.ts` — D1の形をした本物のSQLiteの上で、束ねた設定から会社を組む |
| **ストアの実装差** | メモリのストアだけ | `test/store-contract.ts` — 3実装に同じ契約を当てる |
| **失敗する経路** | 成功する道しか通らない | `refusingProvider()`。失敗の記録は `orchestrator.test.ts` |

## まだ空いているところ

- **`workerd` の上でSDKが動くか。** ローカルでは確かめられない。デプロイして1回通す以外にない。
- **CSSとレイアウト。** ハーネスにスタイルは無い。列幅が潰れるかどうかは見えない。
- **クリックとフォーム。** ハーネスは `document.addEventListener` を握り潰しているので、
  ボタンを押した結果は追えない。**8件のうち1件（実行中にボタンが復活する）は
  いまも自動では捕まらない。** ハンドラを捕まえて合成イベントを渡せば届く。
- **チャネルとASPの本物のAPI。** `threads.ts` はモック越しにしか通っていない。

## 新しいものを足すときの問い

**「これは helpers.ts が置き換えるものの、どちら側か。」**

置き換わる側なら、ユニットテストを1本足しても何も守られていない。
上の表のどの行に載るのかを先に決める。載る行が無いなら、それが新しい帯域で、
**そこを走らせる仕掛けを先に作る。** `page-harness.ts` はそうやってできた。
