# 決めたことと、その理由

決定の記録。**何を決めたか、なぜか、どこに書いてあるか、何がまだ決まっていないか。**
新しい決定は下に足す。覆したときは消さずに「覆した」と書く — なぜ一度そう決めたかは、
次に同じ問いが来たときに効く。

設計そのものは各設計文書に、要件は
[要件定義](../1-requirements/requirements.md)にある。ここはその索引ではなく、
**判断の履歴**である。

## 2026-09 契約

### ライセンサーは個人。将来も個人事業のままでよい

法人格が要る場面は無い。屋号は契約の当事者にならないので署名欄は個人名と住所になる、
という実務上の違いだけ。法人化を考える引き金は4つ（無限責任・税・相手の購買規程・承継）で、
無償でテナントもいない現状はどれも当たらない。

**いま打った手は1つだけ。** 甲が自ら支配する法人へ契約上の地位を承継できる条項を、
契約A第7条と契約B第9条に入れた。これが無いと、法人化したときに
既存のライセンシー全員と結び直しになる。

→ [licensing.md 5.7](../1-requirements/licensing.md)、`contracts/`

### 準拠法は日本法・日本語。読者市場が海外であることとは別

読者が米国にいることは `markets:` の中身の問題で、契約の準拠法とは関係しない。
米国法人がライセンシーになる時点で初めて、英語版と米国側の法務が要る。
ひな型は日本語を先に確定させ、英語版は翻訳ではなく向こうで起草し直す。

### 当面は無償。対価はフィードバック

ライセンシーは自分の事業として運用し、その収益も、テナントに課金するならその料金も
ライセンシーのもの。ライセンサーは請求経路にも取り分にも入らない。
定額・成果連動の文案は契約B第4条の末尾に残してあり、切り替えるときは
消費税・インボイス・監査条項をそのとき整える。

**未決:** 無償契約での免責・責任上限の有効性は法務確認。ひな型は仮置き。

## 2026-09 どこで動かすか

### 既定は Cloudflare Workers。Docker の経路は残す

Vercel と比べた: 無料枠が**商用禁止**（アフィリエイトは確実に該当）、Hobby の Cron は
1日1回が上限で投稿の枠に届かない、Pro は $20/月。Cloudflare は無料枠に非商用条項が無く、
Cron は毎分、**課金が CPU 時間なので待ち時間が数えられない** — 1サイクルの大半は
モデルの応答待ちなので、いちばん高くつくはずの部分がタダになる。$5/月。

無料プランは 10ms CPU で足りない（設定を読んでスコアを計算するだけで超える）ので、
現実解は Workers Paid。

**Worker は入口を1つ増やすだけで、置き換えではない。** `daemon` はそのまま動く。
`workerd` は Node ではないので CLI は手元に残る必要があり、実行環境は2つになる。

→ [hosting.md](../4-operations/hosting.md)、[cloudflare-design.md](../3-development/cloudflare-design.md)

### 保存先は SQL。3テーブル、1行1 JSON

型ごとの列を作った瞬間に、型を変えるたび移行が要る（未決事項 14）。
1行1 JSON なら、いまのファイル版と同じく型の変更に移行が要らない。
`find(predicate)` は JavaScript の述語なので SQL に翻訳する道が無く、
ファイル版と同じく全件読んでメモリで絞る — **挙動が変わらないことが唯一の約束**。

`seq` は並び順のためだけにある。upsert は書き換えないので、差し替えても末尾に動かない。

**判明したこと:** `node:sqlite` が Node に内蔵されている。D1 は SQLite なので、
**本番で D1 が実行するのと同じ文をテストで本物の SQLite に対して走らせられる。**
依存は増えない。設計時に想定していた「フェイクドライバ」は不要になった。

### 停止と非アクティブはポートの向こうへ。安全性の判断はポートの外

`StateStore` の `read` は**同期のまま**。tick は公開する前にこれを見るので、
`await` を挟むと停止を見落とす窓ができる。DB 版は `refresh()` が読んだ
スナップショットから答え、**最初の成功した refresh までは全部 `unreadable`** —
つまり停止扱い。refresh を忘れた入口は止まる側に倒れる。

「読めないときどうするか」は保存先の都合ではなく安全性の本体なので、
`pause.ts`（fail-closed）と `venture-state.ts`（fail-open）に残した。

### `--dry-run` は「何が動いているか」の答えを持たない

一度これを間違えた。`--dry-run` に空の状態ストアを渡したせいで、実機が停止中でも
`doctor --dry-run` は「動いている」と答えた。**確認したいから dry run を打つのに、
実機と違うことを言うのは無意味以下。** 保存先・モデル・アダプタは差し替える。
停止と非アクティブは差し替えない。

→ 実バイナリを起動するスモークテストで固定（`test/cli.smoke.test.ts`）

**未決:** `cycleStartsAt` の「分」が Workers で無視されること（重いサイクルを
1時間 Cron に置いて CPU 15分枠を取るため）を受け入れるか。

## 2026-09 ライセンシーの最初の1時間

### 受け取るのはリンク1つ。clone も YAML も出てこない

Deploy to Cloudflare ボタンが、リポジトリの複製・D1 と Durable Object の作成・
秘密の入力・ビルド・配置・CI/CD をやる。こちらが用意するのは
`wrangler.jsonc`、`.env.example`、`package.json` の説明文、README の1行。

### ドメインは要らない

`workers.dev` のアドレスが無料で公開されるので、`/go/` が初日から動き、
**計測経路が初日に閉じる**。旧ステップ9（ドメインの用意、30分〜、脱落率が最も高い）が
丸ごと消えた。Cloudflare 自身は workers.dev を事業の中核には勧めていないので、
案内は「始めるには十分、育ったら独自ドメインへ」。

### デプロイ画面でモデルの鍵を必須にしない

必須にすると「**鍵を1つも持たずに製品が動くところまで行ける**」という設計の核が、
いちばん最初の画面で壊れる。**合言葉は必須** — 同じアドレスで承認画面が開くため、
そこは後回しにできない。

**2026-09-08 に本当になった。** それまでは半分嘘だった — 出荷している例の設定が
`llm.provider: anthropic` だったので、鍵を入れるまで承認画面が開かなかった。
実デプロイの1画面目で発覚。例を `mock` に変え、鍵は手順4で入れるものにした。

見つからなかった理由が本題で、**スモークテストが例の設定を `mock` に書き換えてから
試していた**。「壊れた例の設定は誰かの初日ではなくここで落ちる」ためのテストが、
落ちようのない形に直してから走っていた。書き換えを外すと12件中10件が赤になる。
README はこの問題を知っていて、直さずに回避策（`--dry-run` を足せ）を書いていた —
端末があれば回避できるが、Cloudflare には端末が無い。

### 設定は承認画面が保存しない。ライセンシーが貼る

Workers のファイルシステムが読み取り専用だから、ではない。**設定はライセンシーのもので、
変更の履歴は本人の控えに残るべき**だから。探索担当の提案を採用したときも同じ経路を通る。

→ [onboarding.md](../2-setup/onboarding.md)、`docs/_drafts/design/onboarding/`

### 壊れていても、リンクと死活だけは答える

`/go/<code>` は、設定が検証に落ちても、合言葉が無くても答える。公開済みの投稿に
入っているリンクは取り消せないし、**記録されなかったクリックは後から数えられない**。
そのためにリダイレクトは `Store` と id と時計しか要求しない（`RedirectDeps`）。
`/healthz` はデータベースより手前。

### Cron の重複はロックで止める。実装は Durable Object

Cron は前回の実行中に発火しうるし、再試行もされる。ロックが無ければ同じ投稿が
2回出る。Durable Object は名前ごとに1つしか存在せず、1度に1リクエストしか扱わない
ので、**それ自体がロック**である。ロックは保持者を記録する — TTL を超えた保持者が
遅れて release したときに、その後に取った人のロックを外さないため。

### ライセンシーのフォークでは、設定を commit する

こちらのリポジトリでは `platform.config.yaml` は git-ignore のまま（実アカウントが
入るため）。**ライセンシーのフォークでは ignore しない。** Cloudflare ではビルドが
設定を Worker に埋め込むので、commit されていない設定は**デプロイが一度も見ない設定**で、
例のまま立ち上がる。リリーススクリプトが `.gitignore` を書き換え、理由もそこに書く。

設定に秘密は入らない（環境変数の名前だけ）という規則があるので、commit しても安全。
これが成り立たなくなったら、この判断も崩れる。

### 検証はアカウント無しでほぼ済んだ（2026-09-04）

`wrangler dev --local` が本物の `workerd` とローカル D1 を立てるので、
「デプロイしないと分からない」と書いた2つはアカウント無しで潰れた。
バンドルは通り（790 KiB）、SDK を含むモジュールグラフは起動し、**1日ぶんの流れが
丸ごと `workerd` の上を通った**（企画10案 → 承認 → 執筆 → 検品 → 枠決め）。

残るのは、本番の鍵が要る Anthropic への実呼び出しと、
ホストされた側（`workers.dev` のアドレス、Cron の実発火、Deploy ボタン）。

### 実デプロイで残り3つのうち2つが片付いた（2026-09-08）

`amp.madbarbarian.workers.dev`。**両方の Cron が自力で発火し**、1日ぶんが
ホストされた側を通った — 毎時Cronが企画からゲートまで、承認のあと執筆・検品・枠決め、
毎分Cronが枠の来た1件だけを公開。ティックが何度走っても公開イベントは1件のまま。

**`/go/` のクリックが1件記録された。** 「ドメインは要らない」は、これで実機の裏付けが
ある。旧ステップ9を消した根拠がここで確定した。

**3番目の画面でいきなり止まった。** 例の設定が `llm.provider: anthropic` で、
鍵が無いと承認画面が開かなかった。スモークテストが例を書き換えてから試していたので
誰も気づいていなかった。→ 別項

残るのは実ストリーミング呼び出しと Deploy ボタンの経路。

## 2026-09 検証を誰がやるか

### 参照環境は自分で持つ。$5 は検証費用ではなく設備

ライセンサーは運用者ではないので、「先行利用者（知人）に動かしてもらいながら
直せばいい」という選択肢があった。**採らない。** 順番を決めたのは費用ではなく、
2つの検証が別のものを試しているという点。

**インフラの不具合はフィードバックではない。** 残っている workers.dev の
アドレス・Cron の実発火・実ストリーミング呼び出しは、動くか動かないかの話で、
相手に見つけさせる種類のものではない。一方**オンボーディングが分かるかどうかは、
書いた本人には試せない** — 初見の目は一度しか使えず、それをバグの発見に
使うのは高すぎる。

**相手の側では目が見えない。** Cloudflare には端末が無いので `doctor` が無く、
相手のアカウントの `wrangler tail` も見られない。動いているものを一度も
見ないまま、動かないものを直すことになる。

順番はどのみち強制されてもいる。ボタンには公開リリースリポジトリとリリース発行が
要り、まだどちらも無い。自分のデプロイはいますぐできる。

無料プランで代用しない。CPU 10ms で落ちたときそれがコードのバグに見えるので、
**曖昧な結果は無い結果より悪い。**

$5/月は1回の検証費ではなく、ライセンサーである限り要る**参照環境**の維持費と
考える。「壊れた」と言われたときに突き合わせる先が無い状態には戻らない。

→ [deploy-checklist.md](../4-operations/deploy-checklist.md)

### 自分の D1 の id は、リリースに乗るファイルに書かない

`wrangler.jsonc` はライセンシーにそのまま届く。id をそこに書くと**全員が
こちらのデータベースを指す設定を受け取る**（開けはしないが、設定としては誤り）。

最初の手順書は「placeholder に戻してから release を切る」と書いていた。
**戻し忘れる手順は、いつか忘れる。** `npm run deploy` が `.env.local` の
`AMP_D1_DATABASE_ID` を見て一時ファイルを作るようにして、戻す手順自体を消した。
変数が無い経路 — つまりライセンシー — は以前と1文字も変わらない。

id は秘密ではないが `.env` ではなく `.env.local` に置く。`.env` は commit される。

## 2026-09 オンボード

### 初期設定は生成器にする。設定ファイルを画面が持ち続けることはしない

ライセンシーの初日は428行の YAML を開くところから始まっていた。
[オンボード設計](../2-setup/onboarding.md)がそこを最大の脱落点と名指ししている。
6問に答えると設定ファイルができあがる形にした（v0.3.0 以降）。

**テキストを埋める。オブジェクトを書き戻さない。** 428行の大半はコメントで、
なぜその値なのかを説明している。パースして書き戻すとそれが消える。
これは承認画面を設定の編集器にしない理由と同じもので、要件3.1に決定として記録した。

### ライセンシーのリポジトリへの書き込みは、いまも「しない」

**貼り付け1回は残す。** 2026-09-12 判断。

中身を URL に載せる案は実測で否定した。GitHub の新規ファイル画面はクエリで本文も
受け取れるが、GET の上限が約2KB、この設定ファイルは URL エンコードで41KB
（日本語がパーセントエンコードで1文字9文字になる）。**ファイル名だけは載る**ので、
「Add file → Create new file → ファイル名を打つ」の3手順は消した。

自動でコミットするには資格情報が要り、形は2つしかない。

| 案 | 状態 |
|---|---|
| 私たちがホストする GitHub App | **却下**（[更新を受け取る](../3-development/taking-updates.md) 4節）。理由はいまも有効 |
| ライセンシーが発行したトークンを自分の Cloudflare に置く | **見送り。** 2つのダッシュボードにまたがる約15手順で、途中で権限スコープを選ぶ必要がある。トークンを知らない人には貼り付け1回より難しい |
| **GitHub Device Flow** | **将来の選択肢。** 下記 |

### 「読むのは画面、変えるのはファイル」は、いまのところ妥協である

**2026-09-12、オーナーからのフィードバック:**「結局、編集はファイルで、になってるんだね。いまいちだよね。」

**そのとおりである。** 上の2つの理由（コメントが消える／真実が2箇所になる）は本物だが、
**理由があることと、使いやすいことは別**である。ライセンシーから見れば
「設定画面があるのに、設定できない」で、それは変な製品である。ここを
「設計上正しいので問題なし」と記録すると、次に読む人が問題を問題として見なくなる。

いまの形は「読む」と「変える」を別の場所に置いた結果で、一貫はしているが親切ではない。
**今回はこれで試すと決めた**（オーナー判断、2026-09-12）。試した結果が、次の判断の材料になる。

**本当に解くなら、画面から変えて、その変更が git のコミットになる形である。**
真実は1箇所のまま、履歴も残る。ただしそれには「ライセンシーのリポジトリに書ける権限」が要るので、
**この課題と下の Device Flow は、実は同じ1つの課題である。** 別々に解こうとしないこと。

### 将来: GitHub Device Flow（未着手）

`github.com/login/device` にコードを入れて承認するだけで、ワーカーがライセンシーの
リポジトリに設定ファイルをコミットできるようになる。貼り付けが消える。

**却下した App 案とは別物である。** 発行されるトークンはライセンシー本人のもので、
1人分だけ、本人がいつでも剥がせる。私たちは何も保持しない
（Device Flow はクライアントシークレットを使わない）。
要件6節「ライセンシーが自分の手元にあるものを監査する」は保たれる。

**いま作らない理由:** ライセンシーがまだ1人もいない。貼り付け1回が本当に脱落点なのかは、
誰かが実際につまずいて初めて分かる。確かめていない問題に工数を使わない。

**着手する条件:** (1) ライセンシーが実際にここで詰まった、または
(2) 最初の1人に見せる体験として、貼り付けを残したくないという営業判断。
