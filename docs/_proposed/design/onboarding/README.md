**提案の板には、板そのものに「提案（未実装）」の印が付く**（右上・破線の囲み）。
`canvas.json` の題名は `canvas.html` にしか出ないので、`.dc.html` を単体で開いた人にも
見えるようにしてある。枠の外に浮かせてあり、画面コピーではない。

いま製品にある経路は **ボタン → セットアップ画面（いまの状態＋7つの質問）→ できた設定を
自分の控えに貼る → 承認画面** で、`src/worker/handler.ts` が答えるのは `/` ・ `/setup` ・
`/unlock` ・ `/go/` ・ `/healthz` だけ。文体のプレビュー・参考投稿・1日を通す・
トークンの検証・案件の登録・最後の確認は、**画面としては存在しない**
（[onboarding.md](../../../2-setup/onboarding.md) の実装表 #3・#4・#8・#9 も同じことを言う）。

**中断して再開する機能は無い。** 進捗を残す `.amp/setup.json` はコードに無く、セットアップ画面は
一度きりのフォームで、答えは送信したその場でしか残らない（`src/worker/handler.ts` の
「the answers are gone either way」）。`Connect.dc.html` は長いあいだ「途中でやめても
続きから再開できます」と端末コマンド付きで案内していた — **端末が無いうえに、機能も無かった。**

**旧ステップ9（リンクのドメインを用意する）は消えた。** `workers.dev` の
アドレスが無料で公開されるため。詳しくは
[Cloudflare で動かす設計](../../../3-development/cloudflare-design.md)。

トークンは承認画面（`src/console/ui.ts`）からの写し。

## 作り直しかた

```bash
npm run build:canvas    # 隣のキャンバスと同時に描き直す
```

板を足したら `canvas.json` にも足す。片方だけだとビルドが止まる。
仕組みは[隣のREADME](../README.md#作り直しかた)。
