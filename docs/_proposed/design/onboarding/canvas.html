ライセンシーの最初の1時間 — 画面設計

生成物です。正本は同じディレクトリの canvas.json と *.dc.html。npm run build:canvas で作り直します。

設計の核: 鍵やトークンを1つも持たずに、製品が動くところまで行けること。外部サービスの手続きは、役に立つと分かってから。

以前の流れ（この設計の逆）: リポジトリの招待 → clone → 428行のYAML。開いた瞬間がいちばん脱落する場所だった。鍵が無いと doctor が最初に止めていた。

旧ステップ9（リンクのドメインを用意する、30分〜、脱落率が最も高い）は消えた。workers.dev のアドレスが無料で公開されるので、計測経路が初日に閉じる。Cloudflare 自身は workers.dev を事業の中核には勧めていないので、案内は「始めるには十分、育ったら独自ドメインへ」。

実装として要るもの: Deploy to Cloudflare ボタン（wrangler.jsonc / .env.example / package.json の説明文 / README 1行）、設定が無い状態で起動してこの画面を出せる Worker、設定の穴埋め生成器、参考投稿からの初期化。文体のプレビュー・鍵の検証・計測経路はすでにある。

この3枚は、鍵もアカウントも要らない。測り方はひとつ: ステップ5に着いた人のうち何人が最後まで行くか。5に着いた人は製品を理解しているので、そこから落ちるなら原因は製品ではなく手順にある。

AIモデルの鍵をこの画面で必須にしない。必須にすると「鍵なしで製品が動くところまで行ける」という設計の核が、最初の画面で壊れる。2026-09-08 まではここが半分嘘で、出荷している例の設定が llm.provider: anthropic だったため、鍵を入れるまで承認画面が開かなかった。実デプロイの1画面目で発覚。例を mock にして、いまは本当に鍵なしで一巡する。合言葉だけは必須 — 同じアドレスで承認画面が開くため。

そしてその合言葉を作るボタンは、Cloudflare の画面に無い。2026-09-11 の実デプロイで確認した — 欄と説明文は出るが、値は自分で入力する。ここは長く「右の『作る』で押せます」と書いていて、押すものが無いまま必須の欄の前に立たせていた。説明文は package.json の cloudflare.bindings にあり、この板と licensee-guide と3つで同じことを言う必要がある。

承認画面は設定を保存しない。Workers のファイルシステムは読み取り専用だが、それ以前に設定はライセンシーのもので、変更の履歴は本人の控えに残るべき。探索担当の提案を採用したときも同じ経路。baseUrl は「足す」ではなく「書き換える」。元の設定に同じ名前があるので、足すと読めなくなる — コードレビューで見つかった。

参考投稿が無いと、初日は型ゼロ・実績ゼロで分析担当が走る。提案品質は初日が最も悪く、しかも初日こそ使えるかを判断する日。だから4は任意だが強く勧める。

残る難所は8だけになった。ここで詰まる人が最も多いので、中断と再開が要件になる。手順4（長期トークンへの交換）のURLは押せるリンクにする。

承認画面がリンクのアドレスに露出する件は、実際のセキュリティレビューで見つかった。/go/ と承認画面は同じところが配る。「計測不能」という期間の記録は実装に無い — 記録されなかったクリックは単に無い。

初日に手作業を1つ足す判断。足したくて足したのではなく、他の選択肢が構造的に閉じている — 判断の全文は docs/3-development/taking-updates.md。

ボタンが作るのは複製でフォークではないので Sync fork が無く、そして GitHub は App に .github/workflows/ を書かせないので、ワークフローは複製に入らない（実デプロイで Actions タブが空だったことで確認）。残る書き手は「本人がブラウザで」か「私たちが全ライセンシーのリポジトリに書き込み権限を持つ」かの2つで、後者はこの製品が売っている「自分で持って監査する」を裏返すので却下した。

ここに置いたのは、初日の最後だから。承認画面が「更新があります」と言えるのは実装済で、それは経路に依存しない。言われた人が動けないことだけが残るので、その1手順を、動ける場所に置く。

ステップ2 — ボタンを押した人が最初に見る画面（v0.7.0 で実装済）。上の板は流れの設計で、これは実物の写し。

バッジは3語しかない。`済` ・ `これから` ・ `あとで`。「あとで」が付くのはAIモデルの鍵だけで、残りの3行は未達なら必ず赤い「これから」になる。3色に見えて、意味は「あなたがいま動くのはどれか」の1つだけを指している。

鍵の行が「あとで」であることが、この製品の設計の核。鍵を必須にすると「鍵なしで製品が動くところまで行ける」が最初の画面で壊れる。だからここは注意色ではなく灰色で、しかも足し方（Cloudflare のどの画面か）をその場で書いてある。

見出しは状態で変わる。設定が無ければ「あと1つ、決めるだけです」、入っていれば「もう少しで、承認画面になります」。残っている作業の数を見出しが言うので、押すたびに減っていくのが読める。

設定を読み込めなかったときだけ、いちばん上に赤い節（`設定を読み込めませんでした`）が挟まる。
