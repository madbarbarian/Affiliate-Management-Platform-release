読めた — **静止した板の向こうに、v0.1.0 から動いている画面がある。** 版はその画面が
**入った版**で、いま動いている版ではない（いまは 0.7.0）。

## 設計上の決めごと

- **トークンは承認画面（`src/console/ui.ts`）からの写し**であって、近似ではない。
  `--bg: #fbfbfa` / `--accent: #2f6f4f` / カード角丸 10px / チップ 999px /
  `15px/1.65 ui-sans-serif, -apple-system, "Hiragino Sans", "Noto Sans JP"`。
  この設計が実装に落ちるとき、CSS を書き直さずに済む。
- **推奨3件は最初からチェック済み**で、残り7件は畳んである。そのまま押せば30秒で終わる。
  疑ったときだけ開く。10案を平等に並べると、30秒では終わらない。
- **枠の時刻は動かせない。** 投稿担当が実測から決めたもの。人間が動かせるのは
  「どれを、どの枠に」だけなので、並べ替えると時刻が付け替わる。
- **詳細画面にも編集はない。** 書き直させた瞬間、人間の仕事は2つでなくなる。
  直したいときは、その投稿を外して明日の企画で言い直す。
- **「判断待ちなし」に会社の動きを出す。** 週の大半はこの画面で、何もないとだけ
  出されると、動いているのか止まっているのか分からない。

## 作り直しかた

`.dc.html` は Claude Design のコンポーネント形式（`<x-dc>` ・ `{{hole}}` ・
`sc-for` / `sc-if` ・ `DCLogic`）。素の HTML ではない。

```bash
npm run build:canvas    # 2つの canvas.html を描き直す
```

`scripts/build-canvas.ts` が `canvas.json` と `.dc.html` から `canvas.html` を描く。
node 標準ライブラリだけで動く。**板ごとに `<iframe srcdoc>` に入れる** —
各 `.dc.html` は自分の `:root` と `body` / `h1` / `.card` を持っているので、
1枚に連結すると最後の1枚の配色で全部が塗り替わる。

**`Main` と `Publish` は動く板**（`{{hole}}` ・ `sc-for` ・ `sc-if`）。
静止画にするために、その板自身の `renderVals()` を評価して埋めている。
だから出るのは placeholder ではなく実物の文面で、状態は初期状態
（推奨3件がチェック済み・残り7件は畳んだまま）。板の見出しに
「動く板 — 初期状態の写し」と付く。

**板を足したら、題名に状態を書く。**語彙は `実装済 v0.3.0` か `提案（未実装）` の2つだけで、
書き忘れると `npm test` が落ちる。**提案の板には、板そのものにも印を置く**
（`.proposal-mark` — 右上・破線の囲み。`canvas.json` の題名は `canvas.html` にしか出ないので、
`.dc.html` を単体で開いた人には題名が見えない）。この14枚に提案の板は無く、実例は
[隣のオンボードのキャンバス](onboarding/README.md)にある。

**板を足したら `canvas.json` にも足す。**片方だけだとビルドが止まる
（`canvas.json` が指すファイルが無い／ディレクトリにあるのに載っていない、の両方）。
`canvas.html` はコミットする。中身が古いと `npm test` が落ちる。

2026-09-19 まで使っていた `seed-canvas.mjs`（Claude の design skill 同梱）は
**いまの skill に無い**。上のリンクがその日の内容で止まっているのはそのため。
**自前で描き出す仕組みを持つ**と決めたのがこの script（2026-09-19 オーナー）。
URLの同一性は要件ではない。
