# 人を増やす — 参照必須

> **利用者・運用者・メンバー・テナント・権限・ロールの話が出たら、実装より先にこれを読む。**
> 決めたのは 2026-09-10。決め直すことはできるが、**同じ議論をやり直さない**ために書いてある。

## 1. まず、どちらの話か見分ける

「人を増やす」には、性質のまったく違う2つが混ざっている。**見分ける問いは1つ。**

> **そのアカウントの報酬は、誰に入るか。**

| | **運用担当者** | **テナント** |
|---|---|---|
| そのアカウントは誰のもの | ライセンシー | その人 |
| 報酬は誰に入る | **ライセンシー** | **その人** |
| ASPと契約しているのは | ライセンシー | その人 |
| 開示違反の責任は | ライセンシー | その人 |
| その人は何者 | ライセンシーの従業員・業務委託先 | 別の事業者 |
| 契約 | ライセンシーとその人の間の業務委託。**ライセンサーは無関係** | 契約C（テナント規約） |
| 契約Bのどこ | 第2条1項(e) | 第6条（別紙） |

**報酬がライセンシーに入るなら、テナントではない。** ここを混ぜると、「権限を付けるか」の話が「SaaS化するか」の話に化ける。

## 2. 決めたこと

### テナントは実装しない

複数の顧客を持ちたいライセンシーには、**顧客ごとに別インスタンス**で足りる。Cloudflare は
$5/月なので5社で$25、分離はアカウントごとに完全、新しいコードはゼロ、事業譲渡は
Worker と D1 ごと渡して終わる。

テナント機構が要るのは、**顧客が数十社になって「ダッシュボードを行き来する手間」が
$5×N より高くつき始めたとき**だけで、そこまで行っていれば判断材料は揃っている。

置くと何が要るかは [licensing.md](../1-requirements/licensing.md) の責任分担表と
[console-architecture.md §5](console-architecture.md) にある。要点は
「利用者データベースを足すのは別の製品を作ること」。

### 運用担当者のロールは実装する。ただし後で

パートナー社に人が入るのはだいぶ先、という前提での判断（2026-09-10）。

**後で足しても壊れない根拠が3つある。この3つが崩れたら、判断はやり直し。**

1. **記録はすでに本物。** 人が動く4箇所すべてに名前が入る — 承認①② (`decidedBy`)、
   非アクティブにする / 再開する (`by`)、探索提案の採用・見送り (`actor`)。
   `router.ts` の `identify()` が返す名前がそのまま流れている。
   **ここが固定文字列だったら「後で」は成立しなかった** — 承認の記録は作り直せない。
2. **ロールは設定の追加項目にできる。** `console.operators[]` に `role:` と `ventures:` を
   足すだけで、既存の `{name, tokenEnv}` はそのまま有効。
   **書いていない運用者は owner** を既定にすること。これを守る限り破壊的変更にならない。
3. **画面はすでに3階層に割れている。** 「全アカウント」と「1つのアカウント」が別なので、
   「この人にはこのアカウントの行しか出さない」を差し込む場所が1箇所に決まっている。

### 順番は「ストア分割 → ロール」

retrofit 順（[multi-venture-architecture.md §5](multi-venture-architecture.md)）のとおり。
理由は権限の保証の強さ。

| | 「この人には雑貨しか見せない」の保証 |
|---|---|
| 今（全アカウントが同じテーブル） | 画面のコードが毎回正しく絞る、という**約束**。`WHERE` を1箇所書き忘れたら隣の売上が見える |
| ストアをアカウントごとに分けたあと | そのセッションでは雑貨のストアしか開かない。**開いていないものは読めない** |

ロールを先に作ると、権限の線を画面の `if` で引くことになり、ストアを分けたときに全部書き直す。

**ストア分割の判断は、人がいつ入るかと無関係。** アカウントの売却にも要り、
移行コストはデータ量に比例して増える。ロールの保留に引きずられて先送りしないこと。

## 3. いまの露出（隠さずに言うこと）

**今日でも2人目は入れられる。** `console.operators` に名前と env 変数を足せば、その人の
承認は本人の名前で残る。**ただし全権**で、他のアカウントの売上も設定も見えるし、
止められる。「このアカウントだけ」は**言葉の上の約束であって、コードの保証ではない**。

人を入れる話が実際に来たときは、これを先に伝える。
