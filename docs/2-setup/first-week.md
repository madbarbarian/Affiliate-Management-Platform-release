# 先行利用者へ — 最初の一週間

> **この文書は古くなっています。** 端末を使うことと、初日から本物のアカウントへ
> 投稿することが前提になっています。最初のテスト利用者にお渡しするのは
> [tester-guide.md](tester-guide.md) です — ブラウザと GitHub だけで終わり、
> 前半では投稿しません。以下の中身はまだ書き換えていません。

このソフトは初日から**実際にあなたのアカウントへ投稿します**。
検証用の空回しではありません。だから最初の3日だけ、条件を3つ付けてください。

3日経ったら普通に回してもらって構いません。この3日は、あなたのアカウントを
守るためというより、**壊れ方を私が見えるようにするため**のものです。

---

## 条件1 — 最初の3日は1日1本、探索枠なし

`platform.config.yaml` の該当する運用アカウントを、こうしてください。

```yaml
    cadence:
      postsPerDay: 1          # 3日経つまで 1。それから 2 に上げる
      minMinutesBetweenPosts: 240
      cycleStartsAt: "06:30"
      ideasPerCycle: 10       # 提案は10案のまま。選ぶのが1本になるだけ
```

設定を変えたら**デーモンを再起動**してください。デーモンは起動時に設定を読み、
その後の変更を見ません。

**なぜ1本か。** 表記まわりのバグが出た場合、被害は本数に比例します。
1日1本なら、気づいてから止めるまでに出るのは最大1本です。

**探索枠は自動で消えます。** `postsPerDay` が2以下のとき、実績のある型で候補が
埋まる限り、未検証の型は提案に入りません。1枠しかないのに探索に使うのは、探索では
なくただの博打なので。3本以上に増やすと、4分の1が自動で探索に戻ります。
例外は、実績のある型がまだ足りないとき。そのときは未検証の型で埋めます。
何も無いより、由来の分かる仮説のほうがいいので。

提案は10案のまま出ます。**選択肢が減るのではなく、選ぶ本数が減るだけ**です。

---

## 条件2 — 承認画面で、本文とPR表記を必ず読む

投稿の承認画面では、**実際に投稿される文章がそのまま開いた状態で出ます**。
折り畳まれていません。案件を含む投稿は、PR表記が入っていれば緑、入っていなければ赤。
案件の無い投稿は「案件なし」とだけ出ます（赤ではありません）。

```
1  07:30  僕が3日で捨てたツールの話。

   ┌────────────────────────────────────┐
   │ 僕が3日で捨てたツールの話。         │
   │                                    │
   │ 去年、作業を速くしたくて…          │
   │                                    │
   │ #PR ※本投稿にはアフィリエイト…     │
   └────────────────────────────────────┘
   PR表記あり #PR ※本投稿にはアフィリエイトリンクを含みます
```

**赤が出たら承認しないでください。** その理由を教えてもらえると助かります
（報告コマンドは準備中なので、当面はメールで）。ガードレールはコードで動いていますが、
それを人が確認できる状態で置いておくのが最後の守りです。

「根拠・指摘・コメント下書き」は畳んであります。読みたいときだけ開いてください。

## 条件3 — 最初の投稿の前に、計測経路を通す

```bash
node src/cli.ts doctor
```

運用アカウントごとに `measurement:` の行が出ます。**`INCOMPLETE` のまま
実投稿を始めないでください。**

```
venture     main — active, 1/day from 06:30 Asia/Tokyo
            measurement: INCOMPLETE
              ✗ the channel reports numbers back
                Channel(s) "threads" use the "mock" adapter. …
              ✗ readers can follow a tracked link
                tracking.baseUrl points at "example.invalid", which a reader cannot reach. …
```

出ている問題は全部、直し方まで書いてあります。全部消えると:

```
            measurement: closed — posts, clicks and revenue all come back
```

**なぜ先に通すのか。** 計測経路が切れたまま1か月回すと、その1か月のクリックは
記録されなかったのであって、ゼロだったのではない。あとから測り直せず、
振り返るときにこの2つは全然違う意味を持ちます。しかも今の版は
その区別を記録しません。切れていた期間は、ただの「数字のない期間」として残ります。

いちばん引っかかるのは3つめの `readers can follow a tracked link` です。
**トラッキングのリダイレクトは承認画面と同じサーバが配信しています。**
`console.enabled: false` にすると、リンクは404になり、クリックは1件も残りません。

## 止めかた

何かおかしいと思ったら、理由を言葉にできる前に止めてください。

```bash
node src/cli.ts pause --reason "案件が違う気がする"
node src/cli.ts resume
```

- デーモンを kill する必要はありません。次のtickで効きます。
- APIキーが切れていても、アダプタが壊れていても、設定ファイルが壊れていても止まります。
- **止めるだけで、捨てません。** 停止中に枠が過ぎた投稿は保持され、
  `resume` 後の最初の配信で出ます。消したいなら resume して見送ってください。

**1つだけできないこと:** チャネル自身のスケジューラが既に受け付けた投稿は
取り消せません。`pause` がその一覧を channel id 付きで出すので、
**チャネル側（Threadsのアプリなど）で消してください。**

## 私に何を送ってほしいか

「動きました」はいちばん困る報告です。以下のどれかがあったら教えてください。

1. **止めたとき** — 何を見て止めたか。直感で構いません
2. **赤いPR表記** — どの投稿で出たか
3. **`doctor` が通らない** — 出力をそのまま
4. **提案が明らかに変** — 10案のうち何案がまともだったか。「3/10」で十分です
5. **数字が合わない** — 承認画面の数字と、チャネル側の実数の食い違い
6. **触りたくなったところ** — 設定で変えられず `src/` を直したくなった箇所。
   **これがいちばん価値のある報告です。** それは機能の不足ではなく、
   設定の設計ミスなので、こちらで直します

毎日の報告は要りません。**上のどれかが起きた日だけ**で構いません。
